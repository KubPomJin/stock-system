## 2. โปรแกรมนี้คืออะไร

- Installer ล่าสุด: `release\StockKeep Setup 1.5.3.exe`

- โปรแกรมคู่: **BillKeep** ที่ `D:\Claude Code\Home\Program\order program\bill-system\`

**git / GitHub** (ตั้งค่าเสร็จแล้ว ใช้ได้เลย)
- repo: **https://github.com/KubPomJin/stock-system** — public, MIT
- `git push` ได้เลยไม่ต้องล็อกอินซ้ำ · **อย่า force push** ถ้าไม่จำเป็น
- ตัวตน commit ตั้งไว้ที่ระดับ repo (`--local`) เป็น noreply ของ GitHub
  เพื่อไม่ให้อีเมลจริงฝังในประวัติสาธารณะ — **อย่าเปลี่ยนไปใช้อีเมลจริง**
- เครื่องนี้มีสองบัญชี GitHub · repo นี้ตั้ง `credential.useHttpPath=true` +
  ใส่ชื่อผู้ใช้ใน remote URL เพื่อไม่ให้หยิบ token ของอีกบัญชีมาใช้
  **อย่าไปลบ credential ของบัญชีอื่นในเครื่อง** จะทำให้โปรเจกต์อื่นต้องล็อกอินใหม่

### v1.4.3 — สรุปการไล่บั๊กเรื่องพิมพ์ (อ่านก่อนแตะโค้ดพิมพ์)

**บทเรียนวิธีทำงาน:** เรื่องพิมพ์เดาไม่ได้ ผมเดาผิดสามรอบก่อนจะเจอของจริงทุกครั้ง
เครื่องมือที่ใช้ได้ผลคือ **`webContents.printToPDF()` เป็น oracle** — ไม่ผ่าน driver
ไม่ผ่านเครื่องพิมพ์ วัดจำนวนหน้า/ขนาด/ระยะได้ตรงๆ **ใช้ตัวนี้พิสูจน์ก่อนแก้เสมอ**
(`Microsoft Print to PDF` ใช้เป็นตัววัดไม่ได้ ผลไม่คงที่)

**ใบตรวจนับ — พังสามชั้นซ้อนกัน แก้ครบแล้ว**
1. หน้าต่างพิมพ์ทั้งสองแบบเลือกเครื่องพิมพ์เริ่มต้นของ Windows เหมือนกัน = **LQ-310
   ที่ไม่มีกระดาษ A4** → driver ปฏิเสธ ขึ้น "Print job failed"
   → แก้: จำเครื่องพิมพ์**แยกตามชนิดเอกสาร** + ข้อความ error บอกชื่อเครื่อง/ขนาดกระดาษ
2. CSS ตอนพิมพ์ล้าง `width`/`padding`/`margin` ของ `.pt-sheet` ครบ **แต่ลืม `height:210mm`**
   ขณะที่พื้นที่จริงมี 190 มม. → **1 ใบ = 2 หน้าเสมอ** (วัดด้วย printToPDF: 2 → 1 หน้า)
3. `silent print` + `Microsoft Print to PDF` = **ไฟล์ 0 ไบต์เสมอ** (spooler ไม่ได้รับข้อมูล)
   → แก้: ถ้าเลือกเครื่องพิมพ์ที่เป็น PDF writer จะเรนเดอร์ด้วย `printToPDF` แล้วเซฟเองแทน

**ใบสั่งสินค้า**
- เอกสารถูกต้องอยู่แล้ว — PDF ที่ส่งออกมี MediaBox **648 × 396 pt = 9.00 × 5.50 นิ้ว** เป๊ะ
  ที่เยื้องบนกระดาษเป็นเรื่องตำแหน่งกระดาษในเครื่อง ไม่ใช่เลย์เอาต์
- เพิ่ม **ช่องตั้งระยะขอบ 4 ด้าน (มม.)** + **เลือกขนาดกระดาษ 9 หรือ 8 นิ้ว** ในหน้าต่างพิมพ์
  ทั้งคู่**จำแยกต่อเครื่อง** (localStorage) เพราะเป็นคุณสมบัติของเครื่องพิมพ์ ไม่ใช่ของเอกสาร
- 🐞 **เส้นกรอบขวาของตารางไม่พิมพ์** — `border-collapse:collapse` วาดกรอบนอกคร่อมขอบ
  เห็นจริงครึ่งเดียว 1.5px จึงเรนเดอร์เป็น **0.8px** (~1.5 จุดที่ 180dpi) บางเกินกว่าเข็มจะตีติด
  → ตั้งกรอบนอกเป็น **3px** ให้ครึ่งที่เห็นได้ 1.5px เท่าเส้นใน (วัดแล้ว 0.8 → 2.4px)

**ยังไม่ได้ทดสอบ / ยังค้าง**
- **พิมพ์ยาว 10+ ใบ** ว่ายังเลื่อนลงสะสมไหม — ถ้าเลื่อน ตัวต้องสงสัยคือ
  **skip over perforation** และ **form length** ที่ตัวเครื่อง LQ-310 (ซอฟต์แวร์คุมไม่ได้)
- **ใบตรวจนับพิมพ์ลงกระดาษจริงไม่ได้ที่เครื่องนี้** — มีเครื่องพิมพ์จริงแค่ LQ-310 ที่ไม่มี A4
  ทำได้แค่ออกเป็น PDF แล้วไปพิมพ์ที่อื่น
- ตาราง `.pt-table` ของใบตรวจนับมีเส้นกรอบนอกบางแบบเดียวกัน ยังไม่แก้เพราะพิมพ์ A4/PDF
  ออกมาปกติ ถ้าเอาไปพิมพ์ดอตแมทริกซ์เมื่อไหร่ให้แก้แบบเดียวกับใบสั่งสินค้า

**ค่า driver ของ LQ-310 ที่ยืนยันแล้วว่าถูก:** ฟอร์มชื่อ `Carbonless papaer 9x5.5`
= 22.86 × 13.97 ซม. = 9.00 × 5.50 นิ้ว, margin 0.00 ทุกด้าน, กราฟิก 180 × 180 dpi
**ขนาดกระดาษที่สร้างเองเป็นค่าเฉพาะเครื่อง ไม่ติดไปกับ installer** — เครื่องใหม่ต้องสร้างเอง

## 4. กติกาสำคัญที่ต้องไม่ทำผิด

1. **สต๊อกเป็น ledger เสมอ** — ทุกการเปลี่ยนแปลงคือการ INSERT แถวใหม่ใน `stock_movements`
   ห้าม UPDATE ยอดคงเหลือตรงๆ · ยอดคงเหลือ = `SUM(qty_change)`
   **การแก้ย้อนหลังทุกกรณีออกเป็น `ADJUST` ตามส่วนต่าง** (หน้าสินค้า / หน้าประวัติ)
2. **ทุกจำนวนเก็บเป็นหน่วยฐาน** (หน่วยเล็กสุด) แปลงเป็นกล่อง/พาเลทตอนแสดงผลด้วย `formatStock()` เท่านั้น
3. **กรองราคา/ต้นทุนตาม role ที่ main process** ไม่ใช่ที่ UI — พนักงาน (level 1) ต้องไม่ได้รับ
   `latest_cost` / ราคาช่าง / ราคาส่ง ผ่าน IPC เลย
4. **migration เพิ่มตาราง/คอลัมน์ทำใน `runMigrations()`** (`src/main/database.ts`) แบบ idempotent
   ห้ามพึ่ง `schema.sql` เพราะมันรันแค่ตอนสร้าง DB ใหม่
5. **ขึ้นเวอร์ชันไปข้างหน้าเท่านั้น** ห้ามติดตั้งเวอร์ชันเก่าทับเวอร์ชันใหม่
6. **BillKeep ห้ามเขียน `stockkeep.db`** — เปิดแบบ readonly เท่านั้น ส่งข้อมูลกลับเป็นไฟล์ `.json`

## 5. เรื่องการพิมพ์ (เคยมีบั๊กใหญ่ ระวังไว้)

- เคยเกิดบั๊ก **พิมพ์ไม่หยุด** เพราะหน้าต่างตัวอย่างเป็น `position:fixed`
  (Chromium ทำซ้ำทุกหน้า) + ตัวแอปเบื้องหลังยังกินพื้นที่ layout
- แก้แล้วโดย: ตอนพิมพ์ใช้ `display:none` กับทุกอย่างยกเว้นแผ่นที่จะพิมพ์ + เปลี่ยน modal เป็น `position:static`
- **มีเพดานจำนวนหน้า** (`pageRanges`) นับจากจำนวนแผ่นที่วาดจริง — สั่ง 1 ใบพิมพ์ได้แค่ 1 หน้า
- **ถ้าจะแก้ CSS การพิมพ์ ให้พิสูจน์ด้วย `webContents.printToPDF()` ก่อนเสมอ** —
  เขียนสคริปต์เล็กๆ โหลด `out/renderer/index.html` ใส่แผ่นพิมพ์ ใส่ body class แล้ววัด
  จำนวนหน้า/MediaBox/ระยะจริง **อย่าใช้ Microsoft Print to PDF เป็นตัววัด — ผลไม่คงที่**
  (silent print กับมันได้ไฟล์ 0 ไบต์ และเคสเดียวกันให้ผลต่างกันคนละรอบ)
- ขนาดกระดาษ: ใบตรวจนับ = A4 (เลือกแนวได้), ใบสั่งสินค้า = **9 × 5.5 นิ้ว**
  (พิมพ์ได้จริง 8 นิ้วหลังหักขอบรูฟันเฟือง — ตั้งระยะขอบเองได้ในหน้าต่างพิมพ์)
- เครื่องพิมพ์: EPSON LQ-310 (dot matrix) — เส้นต้องหนา 1.5px ไม่งั้นจางหาย
  **ระวัง `border-collapse:collapse`: กรอบนอกเห็นแค่ครึ่งเดียว ต้องตั้ง 2 เท่า**
  และต้องตั้ง Custom Paper Size ใน driver ให้ตรงด้วย

## 8. เคล็ดลับให้แชตใหม่ประหยัด context

1. **อย่าให้ Claude อ่านไฟล์ทั้งไฟล์ถ้าไม่จำเป็น** — บอกให้ `grep` หาบรรทัดที่ต้องแก้ก่อน
   (`src/renderer/index.html` ใหญ่มาก ~78KB อ่านทั้งไฟล์กินพื้นที่เยอะ)

4. **อัปเดตไฟล์นี้ทุกครั้งที่จบงานใหญ่** — บอก Claude ว่า "อัปเดต HANDOFF.md ด้วย"
