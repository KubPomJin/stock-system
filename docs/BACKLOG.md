## 1. งานค้างที่ต้องทำต่อ (เรียงตามความสำคัญ)

### 1.1 กรอกข้อมูลสินค้าเข้าโซน ⬅️ **งานเดียวที่ค้างจริง**

หน้า **ผังโกดัง** สร้างเสร็จและใช้งานได้ แต่ยังไม่มีข้อมูลว่าสินค้าไหนอยู่โซนไหน
(ทุกโซนขึ้น 0 รายการ) ค้นหาไปก็ยังไม่เจออะไร

- ข้อมูลอยู่บน **กระดาษที่เจ้าของร้านเขียนไว้** บอกว่าถ่ายรูปแล้วแต่ **ยังไม่ได้ส่งเข้ามาในแชต**
  (ที่ส่งมามีแต่รูปผังโกดังเปล่า)
- **สิ่งที่ต้องขอ:** รูปกระดาษที่ระบุว่าโซน 1–13 แต่ละโซนมีสินค้าอะไรบ้าง
- กรอกได้ 2 ทาง: หน้าผังโกดัง (เลือกโซนแล้วเพิ่มสินค้า) หรือ **หน้าสินค้า → ติ๊กหลายรายการ
  → เลือกโซน → "เพิ่มลงโซน"** ซึ่งเร็วกว่ามากถ้ามีข้อมูลเป็นชุด
- ทางลัด: กรองชิป **"ยังไม่ระบุ"** เพื่อไล่เก็บของที่ยังไม่ได้จัดที่

### 1.2 กระดาษเลื่อนสะสมตอนพิมพ์ใบสั่งสินค้ายาว — **แก้ที่เครื่อง ไม่ใช่ที่โค้ด**

พิมพ์ต่อกันหลายใบแล้วฟอร์มค่อยๆ เลื่อนลงจนชนขอบ

- **พิสูจน์แล้วว่าไม่ใช่ซอฟต์แวร์** — เรนเดอร์ 10 แผ่นด้วย `printToPDF` ได้ MediaBox
  9.00 × 5.50 นิ้วเท่ากันทุกแผ่น ขอบซ้าย-ขวา 12.7 มม. เท่ากันทุกแผ่น ไม่มีการเลื่อนสะสมเลย
- ต้นเหตุอยู่ที่ **form length** และ **skip over perforation** ที่ตัวเครื่อง LQ-310
  ซึ่งซอฟต์แวร์อ่านค่าและควบคุมไม่ได้
- เคยทำ **ช่องปรับความสูงหน้ากระดาษ** ไว้ชดเชย (v1.5.2) แต่เจ้าของเลือกไม่ใช้
  จึงถอดออกใน v1.5.3 — **โค้ดยังอยู่ใน git ที่ commit `66046c1`** ถ้าอยากได้กลับมาดึงได้เลย

## 3. การตัดสินใจเชิงออกแบบที่ต้องรู้ (อย่าเปลี่ยนโดยไม่คิดให้ครบ)

### 3.0 หลายระดับหน่วย — ยังไม่ใช้ จนกว่าจะมีตัวคูณที่แน่นอน (25 ส.ค. 69)

เจ้าของร้านยืนยันว่า **ยังไม่มีตัวเลขแปลงที่ชัดเจน** (1 กล่องมีกี่ชิ้นไม่คงที่/ยังไม่ได้นับ)
และจะ **พิมพ์จำนวนเองโดยตรง** จึงตกลงว่า:

- **ตั้งสินค้าให้มีหน่วยเดียว** = หน่วยที่นับจริง แล้วกรอกตัวเลขตรงๆ
- **ห้ามใส่ระดับหน่วยเพิ่มจนกว่าจะรู้ตัวคูณจริง** เพราะ `qtyPerBase` ถูกใช้คำนวณเงียบๆ
  ใน 3 ที่: การแสดงยอด (`formatStock`), ช่องกรอกตรวจนับแยกหน่วย, และคอลัมน์ราคาต่อหน่วย
  ตัวคูณผิด = ตัวเลขผิดทั้งสามที่โดยไม่มีอะไรเตือน
- พอเป็นหน่วยเดียว ระบบไม่คำนวณอะไรเลย ทุกอย่างเป็นค่าที่คนกรอก
- เพิ่มระดับหน่วยทีหลังได้โดยไม่ต้องรื้อข้อมูลเดิม

> เดิมข้อมูลทดสอบตั้ง "กล่อง" เป็นหน่วยฐาน (×1) แล้วให้ ชิ้น=50, ถุง=200 ซึ่งกลับด้าน
> (หน่วยฐานต้องเป็นหน่วย**เล็กที่สุด**เสมอ) — ถ้าเจอข้อมูลแบบนี้ในระบบให้แก้เป็นหน่วยเดียวก่อน



### 3.1 โซนโกดังไม่ใช่มิติของสต๊อก

`zones` / `product_zones` เป็น **ตัวช่วยหาของเท่านั้น** ไม่ได้แตะ `stock_movements` เลย
ยอดคงเหลือยังนับตาม `locations` (คลังสินค้า / หน้าร้าน) เหมือนเดิม

**เหตุผล:** ถ้าทำโซนเป็นมิติของ ledger จะต้องระบุโซนทุกครั้งที่รับของ/เบิกของ/ตรวจนับ
ซึ่งเป็นการรื้อระบบสต๊อกทั้งระบบ และไม่ใช่สิ่งที่เจ้าของขอ (เจ้าของขอ "ตัวช่วยหาของ")

### 3.2 หน้าผังโกดังต้องไม่ส่งราคาผ่าน IPC

พนักงาน (level 1) ใช้หน้านี้ได้ ดังนั้น `src/main/ipc/zones.ts` ส่งเฉพาะ
`id / barcode / description / baseUnit / barcodePending` **ไม่มี cost หรือราคาทุกชั้น**
คงกติกาความปลอดภัยข้อ 1 ของโปรเจกต์ไว้ — **ถ้าจะเพิ่ม field ต้องระวังข้อนี้**

### 3.3 ผังเก็บเป็นข้อมูล ไม่ฝังในโค้ด

ตำแหน่งช่องอยู่ใน `zones.grid_col/grid_row/grid_w/grid_h` บนกริด **40 คอลัมน์**
(40 เพราะแถวบนแบ่ง 5 ช่อง แถวล่างแบ่ง 8 ช่อง — 40 คือความกว้างเล็กสุดที่ลงตัวทั้งคู่)
ปรับผังทีหลังได้โดยไม่ต้องแก้โปรแกรม

`kind` มี 3 แบบ: `zone` (เก็บของ กดได้) · `label` (ประตู/ออฟฟิศ) · `space` (ช่องว่างจัดรูปผัง)

### 3.4 ระยะขอบกระดาษและขนาดกระดาษเป็นค่า "ต่อเครื่อง"

เก็บใน `localStorage` ไม่ใช่ในฐานข้อมูล เพราะเป็นคุณสมบัติของ**เครื่องพิมพ์**ที่ต่อกับเครื่องนั้น
ไม่ใช่ของเอกสาร ถ้าฝังลงเลย์เอาต์ เครื่องที่กระดาษตรงอยู่แล้วจะเยื้องผิดทางแทน

คีย์ที่ใช้: `print.orderMargins`, `print.orderPaper`, `printer.orderTicket`, `printer.stocktake`

## 4. บทเรียนวิธีทำงานที่ควรจำ

### 4.1 เรื่องพิมพ์ — ห้ามเดา ให้วัด

ไล่บั๊กเรื่องพิมพ์ในรอบ v1.4.2–v1.4.3 **เดาผิดสามรอบ** ก่อนเจอต้นเหตุจริงทุกครั้ง
เครื่องมือที่ใช้ได้ผลคือ **`webContents.printToPDF()` เป็น oracle**:

```js
// สคริปต์ทิ้งขว้าง: โหลด out/renderer/index.html → ใส่แผ่นพิมพ์ → set body class
// → printToPDF → นับหน้า / อ่าน MediaBox / วัดระยะจาก getBoundingClientRect
```

ไม่ผ่าน driver ไม่ผ่านเครื่องพิมพ์ ผลคงที่ วัดได้จริง

**ห้ามใช้ `Microsoft Print to PDF` เป็นตัววัด** — silent print กับมันได้ไฟล์ **0 ไบต์**
และเคสเดียวกันให้ผลต่างกันคนละรอบ

### 4.2 ปิดโปรแกรมก่อน build เสมอ

- `npm run dist` ต้อง rebuild native module (`better-sqlite3`) ที่โปรแกรมล็อกไว้ → **EBUSY** ถ้าเปิดอยู่
- `npm start` ตอนที่โปรแกรมเปิดอยู่จะโดน **single-instance lock เตะทิ้งเงียบๆ (exit 0)**
  แล้วโฟกัสหน้าต่างเก่าแทน — **เคยทำให้ทดสอบโค้ดเก่าไปหนึ่งรอบเต็มโดยไม่รู้ตัว**
  → เช็ค process ก่อนเปิดทุกครั้ง

### 4.3 สภาพแวดล้อมของเครื่องนี้

- `node` **ไม่อยู่ใน PATH ของ Git Bash** → ต้องรัน `npm` ผ่าน **PowerShell**
- `better-sqlite3` ถูก build ไว้ให้ **Electron ABI** → รันด้วย `node` ธรรมดาจะ error
  `NODE_MODULE_VERSION` · **ห้าม `npm rebuild`** เพราะจะพัง Electron
  → อ่าน DB ด้วย: `$env:ELECTRON_RUN_AS_NODE="1"; .\node_modules\electron\dist\electron.exe script.js`
- PowerShell tool: cwd หลุดได้ → ใส่ `Set-Location` เต็ม path ทุกครั้ง

## 5. ข้อมูลสำรองที่ต้องรู้

**เครื่องพิมพ์ EPSON LQ-310** (ยืนยันแล้วว่าตั้งถูก)
- ฟอร์มชื่อ `Carbonless papaer 9x5.5` = **22.86 × 13.97 ซม. = 9.00 × 5.50 นิ้ว**
- margin **0.00 ทุกด้าน** · กราฟิก **180 × 180 dpi**
- ⚠️ **ขนาดกระดาษที่สร้างเองเป็นค่าเฉพาะเครื่อง ไม่ติดไปกับ installer** — เครื่องใหม่ต้องสร้างเอง
  ไม่งั้นฟอร์มจะเยื้องจนขอบขวาหาย

**เครื่องพิมพ์ที่มีในเครื่องนี้** — มีเครื่องจริงแค่ **LQ-310** ตัวเดียว
(ที่เหลือคือ Adobe PDF / OneNote ×2 / Microsoft XPS / Microsoft Print to PDF / Fax = เสมือนทั้งหมด)
→ **ใบตรวจนับ A4 พิมพ์ลงกระดาษจริงที่เครื่องนี้ไม่ได้**

**ฐานข้อมูล** — `%APPDATA%\stockkeep\stockkeep.db`
- สำรองก่อนทำ migration ใหม่ไว้ที่ scratchpad ชื่อ `stockkeep.before-zones.db` (24 ส.ค. 2569)
- ลบ installer เก่าทิ้งแล้ว เหลือแค่ตัวล่าสุดใน `release/`
