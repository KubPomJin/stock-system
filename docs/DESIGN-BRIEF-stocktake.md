# Design brief — หน้า "ตรวจนับสต๊อก" (StockKeep)

> เอกสารนี้ทำไว้ให้เอาไปวางใน Claude / นักออกแบบ เพื่อขอแบบหน้าจอที่สวยและใช้ง่ายขึ้น
> ไฟล์ประกอบ: `docs/mockup-stocktake.html` (เปิดในเบราว์เซอร์ดูได้เลย = สภาพหน้าจอปัจจุบัน)

---

## 1. พรอมต์สำหรับส่งให้ Claude (คัดลอกทั้งบล็อกนี้ไปวางได้เลย)

```
ช่วยออกแบบ UI ใหม่ให้หน้า "ตรวจนับสต๊อก" ของโปรแกรมจัดการสต๊อกสินค้า (desktop app ภาษาไทย)
ส่งกลับมาเป็นไฟล์ HTML ไฟล์เดียว มี CSS อยู่ในไฟล์ ไม่ต้องใช้ framework หรือ CDN ใดๆ
(โปรแกรมจริงเป็น Electron + vanilla HTML/CSS/TS ไม่มี React)

## บริบทงานจริง
ร้านวัสดุก่อสร้างในไทย พนักงานจะ:
1. พิมพ์ใบตรวจนับออกมาเป็นกระดาษ
2. เดินนับของจริงตามชั้นวาง เขียนตัวเลขลงกระดาษ
3. กลับมานั่งคีย์ตัวเลขจากกระดาษเข้าหน้าจอนี้ทีละรายการ

คนคีย์คือคนนั่งหน้าคอม ตาสลับไปมาระหว่างกระดาษกับจอตลอดเวลา
สินค้ามีได้หลายร้อยรายการ ต้องคีย์เร็วและไม่หลงบรรทัด

## ข้อมูลที่ต้องแสดงต่อ 1 สินค้า
- บาร์โค้ด, ชื่อสินค้า, หน่วยฐาน (เช่น ชิ้น / กล่อง)
- ต่อสถานที่ (ตอนนี้มี 2 ที่: "คลังสินค้า" และ "หน้าร้าน") แต่ละที่ต้องมี:
  - จำนวนที่ระบบมีอยู่ (อ่านอย่างเดียว)
  - ช่องกรอก "นับได้จริง"
  - ผลต่าง (ขาด / เกิน / ตรงกัน) แสดงทันทีที่พิมพ์
- รวมทุกคลัง: ยอดระบบรวม + ยอดนับรวม + ผลต่างรวม
- ของเข้า (ไม่บังคับ): ติ๊กว่ามีของเข้า + จำนวน + วันที่
- หมายเหตุผู้นับ (ข้อความสั้นๆ อธิบายเหตุผลของผลต่าง)

ด้านบนของหน้ามีฟอร์มหัวเอกสาร: เลขที่เอกสาร, วันที่นับ, เวลาที่นับ, ชื่อผู้นับ,
หมวดหมู่, หมายเหตุรวม, และตัวเลือก "บันทึกแบบไม่ออกเลขที่เอกสาร"

## ปัญหาที่ต้องแก้ (สำคัญที่สุด)
1. **ตารางกว้างเกินจอ ต้องเลื่อนซ้าย-ขวาตลอด** ทำให้หลงบรรทัดและอ่านยาก
2. คีย์ข้อมูลช้า เพราะต้องเลื่อนหาช่องกรอก
3. ดูไม่ออกว่ารายการไหนคีย์แล้ว / ยังไม่ได้คี้
4. ตัวหนังสือสีเทาจางเกินไปในบางจุด อ่านยาก

## สิ่งที่อยากได้
- **ไม่ต้องเลื่อนซ้าย-ขวาเลย** บนจอ 1366×768 ขึ้นไป
- คีย์ด้วยคีย์บอร์ดล้วนได้ (Tab / Enter ไล่ช่องถัดไปอย่างเป็นธรรมชาติ)
- เห็นชัดว่ารายการไหนนับครบแล้ว รายการไหนมีผลต่าง
- ช่องกรอกใหญ่พอ ตัวเลขอ่านง่าย (คนใช้อายุ 40+ ด้วย)
- มีตัวกรอง: ค้นหา, เฉพาะที่ยังไม่นับ, เฉพาะที่มีผลต่าง
- สรุปด้านบนหรือล่าง: นับแล้วกี่ช่อง / พบผลต่างกี่รายการ / มูลค่าผลต่างรวม
- ปุ่ม "บันทึกผลการตรวจนับ" ต้องหาเจอง่าย และไม่กดโดนโดยบังเอิญ

เสนอมา 2 แนว: (ก) แบบตาราง compact  (ข) แบบการ์ดทีละสินค้า/โฟกัสทีละรายการ
บอกข้อดีข้อเสียของแต่ละแบบสั้นๆ ด้วย

## สไตล์ที่ต้องรักษาไว้ (ให้เข้ากับโปรแกรมเดิม)
- สีหลัก (ส้ม): #DC7A16   สีเข้ม: #B4620F   สีอ่อน: #FBEBD8
- พื้นหลังแอป: #EEF1F2   พื้นการ์ด/พาเนล: #FFFFFF   เส้นขอบ: #DEE3E5
- ตัวอักษรหลัก: #1A1F22   ตัวอักษรรอง: #6D767B
- เขียว(ปกติ): #2F7D52   เหลือง(เตือน): #B8790F   แดง(ผิดปกติ): #C0392B
- ฟอนต์: 'Noto Sans Thai', 'Leelawadee UI', 'Segoe UI', sans-serif
- ตัวเลข/บาร์โค้ดใช้ฟอนต์ monospace
- มุมโค้ง 6px (ปุ่ม/ช่องกรอก), 10px (พาเนล)
- แบนๆ สะอาด ไม่มี gradient ไม่มีเงาฟุ้ง
- UI ภาษาไทยทั้งหมด
```

## 2. ข้อมูลเสริมถ้าเขาถามต่อ

- **จอที่ใช้จริง:** โน้ตบุ๊ก Windows ความละเอียด 1366×768 ขึ้นไป (ไม่ต้องรองรับมือถือ แต่รองรับได้ก็ดี)
- **จำนวนรายการ:** หลักสิบถึงหลักร้อย ต่อการนับหนึ่งรอบ
- **สถานที่:** ตอนนี้ 2 แห่ง แต่ในฐานข้อมูลเป็นตาราง เพิ่มได้ในอนาคต — ดีไซน์ควรรองรับ 3 แห่งได้โดยไม่พัง
- **หน่วย:** ระบบเก็บเป็น "หน่วยฐาน" (หน่วยเล็กสุด) แล้วแปลงตอนแสดงผล เช่น 163 ชิ้น → "6 กล่อง 19 ชิ้น"
- **สิ่งที่ห้ามตัดออก:** ช่องของเข้า (ติ๊ก/จำนวน/วันที่) และหมายเหตุผู้นับ — ธุรกิจใช้จริง

## 3. เอาแบบที่ได้กลับมาใช้ยังไง

ส่งไฟล์ HTML ที่ได้กลับมา แล้วบอกผมว่า "เอาดีไซน์นี้ไปใช้กับหน้าตรวจนับ"
ผมจะแปลงเป็นโค้ดจริงในโปรแกรม (แก้ `src/renderer/index.html` +
`src/renderer/src/views/stocktake.ts`) โดยที่ตรรกะการบันทึก/ตัดสต๊อกยังเหมือนเดิม
