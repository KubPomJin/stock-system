## ธุรกิจที่ใช้งาน
ร้าน/โกดังวัสดุก่อสร้างในไทย (เหล็ก, ตาข่าย, น็อต, ท่อ)
ผู้ใช้ 3 กลุ่ม: พนักงานหน้าร้าน, คนจัดสต็อก, เจ้าของร้าน
คนใช้ส่วนใหญ่อายุ 35-60 ไม่ถนัดคอมพิวเตอร์มาก ตัวหนังสือเล็กเกินไปจะใช้ลำบาก

## หน้าจอทั้งหมดที่ต้องออกแบบ
1. **เข้าสู่ระบบ** — ชื่อผู้ใช้ / รหัสผ่าน
2. **แดชบอร์ด** — การ์ด KPI 4 ใบ (จำนวนสินค้า, ต่ำกว่าขั้นต่ำ, มูลค่าสต๊อก, ยังไม่มีสต๊อก)
   + แถบเตือนสินค้าติดลบ/ต่ำ + ตารางสินค้าที่ต่ำกว่าขั้นต่ำ
3. **สินค้า** — ตารางรายการสินค้า + ค้นหา + ชิปกรองหมวดหมู่/สถานะ + ปุ่มเพิ่มสินค้า
   (คอลัมน์: บาร์โค้ด, ชื่อ, หมวด, หน่วยฐาน, สต๊อกแยกคลัง, ต้นทุน, ราคา 3 ระดับ, สถานะ)
   + ฟอร์มเพิ่ม/แก้สินค้าแบบ slide-over (บาร์โค้ด, ชื่อ, หมวด, โครงสร้างหน่วยหลายระดับ,
     สต๊อกขั้นต่ำ/สูงสุด, สต๊อกตั้งต้นแยกคลัง, ราคา 4 ช่อง)
4. **รับสินค้า** — หัวเอกสาร (เลขที่, วันที่, ผู้จำหน่ายแบบพิมพ์ค้นหา/เพิ่มใหม่ได้, คลังปลายทาง)
   + ฟอร์มเพิ่มรายการ + ตารางรายการ + สรุปยอด (ก่อนภาษี/VAT/รวม)
5. **เบิกของ** — เลือกต้นทาง→ปลายทาง (มีปุ่มสลับ) + เพิ่มรายการ + แสดงคงเหลือหลังเบิก
6. **ตรวจนับสต๊อก** — หน้าที่ซับซ้อนที่สุด ดูหัวข้อ "โจทย์พิเศษ" ด้านล่าง
7. **ประวัติสต๊อก** — 2 แท็บ: "รอบการตรวจนับ" และ "การเคลื่อนไหวทั้งหมด" (ledger)
   มีชิปกรองประเภท + ค้นหา + ปุ่มดูรายละเอียดรอบ (เปิด modal)
8. **เชื่อมระบบบิล** — นำเข้าไฟล์ .json จากโปรแกรมบิล + ส่งออกรายการสินค้า + ประวัติการนำเข้า
9. **ใบสั่งสินค้า** — พิมพ์ฟอร์มเปล่าพร้อมเลขรัน (เลือกเล่ม A/B/C/D, เลขเริ่มต้น, จำนวนใบ)
   + (เสริม) กรอกในระบบแล้วพิมพ์ + ประวัติใบที่บันทึก
10. **ผู้ใช้งาน** (เฉพาะเจ้าของร้าน) — ตารางผู้ใช้ + สิทธิ์ + ปุ่มสำรอง/กู้คืนฐานข้อมูล
11. **หน้าต่างพิมพ์** — modal 2 คอลัมน์: ซ้ายเลือกเครื่องพิมพ์/จำนวนสำเนา/แนวกระดาษ
    ขวาเป็นตัวอย่างกระดาษขนาดจริง

## โจทย์พิเศษ: หน้าตรวจนับสต๊อก (สำคัญที่สุด)
พนักงานพิมพ์ใบตรวจนับ → เดินนับของเขียนใส่กระดาษ → กลับมานั่งคีย์เข้าหน้าจอ
ต้องแสดงต่อ 1 สินค้า:
- บาร์โค้ด, ชื่อ, หน่วยฐาน
- ต่อสถานที่ (ตอนนี้ 2 แห่ง: คลังสินค้า / หน้าร้าน): ยอดในระบบ (อ่านอย่างเดียว),
  ช่องกรอก "นับได้จริง", ผลต่าง (ขาด/เกิน/ตรง) แสดงทันที
- รวมทุกคลัง: ยอดระบบรวม + ยอดนับรวม + ผลต่างรวม
- ของเข้า: ติ๊กว่ามีของเข้า + จำนวน + วันที่
- หมายเหตุผู้นับ
**ห้ามต้องเลื่อนซ้าย-ขวา** และต้องคีย์ด้วยคีย์บอร์ดรัวๆ ได้ (Tab/Enter ไหลลื่น)
ต้องเห็นชัดว่ารายการไหนคีย์แล้ว/ยังไม่คีย์/มีผลต่าง

## ปัญหาปัจจุบันที่อยากให้แก้
1. ตารางหลายหน้ากว้างเกินจอ ต้องเลื่อนซ้าย-ขวา
2. ตัวหนังสือสีเทาจางหลายจุด อ่านยากโดยเฉพาะคนสายตาไม่ดี
3. หน้าตาเรียบเกินไป ดูไม่ออกว่าอะไรสำคัญกว่าอะไร
4. ฟอร์มยาว ต้องเลื่อนลงเยอะ
5. ปุ่มสำคัญ (บันทึก) กับปุ่มทั่วไปดูใกล้เคียงกันเกินไป

## สิ่งที่อยากได้
- ใช้งานได้เต็มที่บนจอ 1366×768 โดยไม่ต้องเลื่อนซ้าย-ขวา
- ลำดับความสำคัญของข้อมูลชัดเจน (ตัวเลขสำคัญต้องเด่น)
- ตัวหนังสืออ่านง่าย คอนทราสต์เพียงพอ (สีเทาอ่อนใช้เท่าที่จำเป็น)
- สถานะสี: ปกติ / ต่ำกว่าขั้นต่ำ / ติดลบ ต้องแยกออกจากกันในพริบตา
- ปุ่มหลักเด่นชัด ปุ่มอันตราย (ลบ/เขียนทับ) ต้องดูต่างจากปุ่มทั่วไป
- ตารางยาวๆ อ่านง่าย (แถวสลับสี / หัวตารางค้างเวลาเลื่อน)
- เมนูซ้ายบอกได้ว่าอยู่หน้าไหน
- ยังคงความ "แน่น" แบบโปรแกรมทำงาน ไม่ใช่เว็บโปรโมทที่โปร่งเกินไป

  คนจัดสต็อก, เจ้าของร้าน — เมนูและคอลัมน์ต้องซ่อนตามสิทธิ์

## 3. เอาแบบที่ได้กลับมาใช้ยังไง

ส่งไฟล์ HTML ที่ได้กลับมา แล้วบอกว่า **"เอาดีไซน์นี้ไปใช้"**
ผมจะแปลงเป็นโค้ดจริงทีละหน้า (แก้ `src/renderer/index.html` และไฟล์ใน
`src/renderer/src/views/`) โดยที่ตรรกะฐานข้อมูล/การตัดสต๊อก/ระบบสิทธิ์ **ไม่เปลี่ยน**

> แนะนำให้ทยอยเปลี่ยนทีละหน้า (เริ่มจากหน้าที่ใช้บ่อยที่สุด) จะได้ทดสอบง่ายและถอยกลับได้ถ้าไม่ถูกใจ
